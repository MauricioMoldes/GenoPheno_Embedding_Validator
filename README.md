## Testing pertubations of the Haplograph --> Evo2 genomic model to see what works best in particular settings.  

As a POC, builds a haploblock co-occurrence graph from the [1000 Genomes haplograph](https://data.haploblocks.org/haplograph/1000G/), turns its nodes into embeddings with Node2Vec, GNN or XGBoost, and fine-tunes Evo 2 (7B) on those embeddings.  We have fine tuned Evo2 embeddings generated by XGBoost without the graph, and established a baseline for comparison by fine tuning Evo2 with binary strings generated directly with unlinked haploblocks.  

We have also mirrored this analysis with cancer data, but also generated embeddings for proteins using XGBoost with and without the graph and GNN, and used them to tune ProLM.  

For validation/comparison, we will use a 50/50 test train set to build and execute graphs at least two connections per node.  This will establish model consistency with respect to generation of and assignment to etiologies.

We will also test how many of the haploblocks in question have SNPs identified by GWAS consortia and other clinical tests.

In the future, for deleterious phenotypes we will assess how well individual etiologies respond to drugs.  For those that do not we can recommend them for data generation and drug development pipelines.  

For more see: [haploblocks.org](haploblocks.org)

- xgboost (XGBoost embeddings)
- evo2 + flash-attn (step 4)

## Usage

Run the scripts in order. Step 1 writes the graph to `haplograph/genome/`; steps 2–4 read and write there (change with `--graph-dir`).

```bash
python 1_build_graph.py                            # whole genome (or --chroms chr21,chr22)
python 2_ancestry_labels.py                        # needed for xgboost or --objective ancestry
python 3_node_embeddings.py --method node2vec      # or gnn / xgboost
python 4_finetune_evo2.py   --method node2vec      # --objective next (default) or ancestry
```

Add `--chroms chr21,chr22` to any step for a quick test run, and `--help` to see all options.

## Proteomics preparation (paired tumor/normal)

[`proteomics_prep/`](proteomics_prep/) holds R scripts that prepare paired tumor/normal proteomics for the early
versus late fusion tests. They place each protein in the haploblock that holds its gene's transcription start
site, compute tumor minus normal per protein and patient, and write node and edge CSVs (patients, blocks,
proteins, protein-to-block edges) plus a protein × patient matrix. Each block also carries its haplograph id
(`chr21_14215892-14284114`), so proteins can be joined to the cluster nodes from `1_build_graph.py` by prefix.
See [`proteomics_prep/README.md`](proteomics_prep/README.md).
